เทคนิค/Skills/Workflow น่าลอง

🧪 Pattern: “Done Means State Changed” — ใช้กับ agent ที่แก้ระบบจริง; template: goal -> expected external state -> verification query -> screenshot/log/db evidence -> rollback note; verify ด้วย backend state ตามแนว ThinkingBox

🛡️ Pattern: “Action Permission Ladder” — ใช้เมื่อ agent มี browser/CLI/tool access; เริ่มจาก read-only, draft-only, sandbox write, human-approved side effect, แล้วค่อย production action; caveat: ต้อง log denial/approval events อ้างอิง Anthropic unintended actions

🧩 Pattern: “Small-Model Subagent Pool” — ใช้กับงานซ้ำ/ปริมาณสูง เช่น summarize, classify, compact, extract; route งานง่ายไป Haiku-class model แล้วให้โมเดลใหญ่ตรวจเฉพาะ risky outputs; verify ด้วย sample-based eval และ cost dashboard อ้างอิง Claude Haiku 5.5

🔎 Pattern: “Lazy Tool Surface” — ใช้เมื่อ MCP/tools เยอะจน context แพง; ให้ agent ค้นหา/โหลดเฉพาะ tool schema ที่เกี่ยวข้องก่อน execute; caveat: ต้องมี fallback เมื่อเลือก tool ผิด อ้างอิง OpenAI MCP docs และ Tool Attention paper
